# P4 — план второй фазы

База анализа: `aafb5119567e90507eb2879f14be6c1d4e4d7c89`, Garda 1.4.4.
Это план для владельца R7/update после объединения universal-base. Продуктовые изменения здесь не сделаны.
При интеграции сначала повторить соответствующий новый acceptance: уже устранённый merged-base дефект повторно не исправлять.

Исходные требования: bounded T-441, T-450-1-F1, T-457, focused T-406/T-408 и §8 концепции.
Тесты и способ воспроизведения: `tests/node/migration/README.md`.

Порядок: общий R7 projection → повтор focused acceptance → недостающие consumer/producer изменения → legacy alignment
→ update interruption/handoff qualification → affected-lane economy guards. Совместимость, integrity и freshness
согласовать с core owner; не создавать независимый migration engine.

P4 suite запускается отдельно: текущий список каталогов `npm test` не включает `tests/node/migration`.
Включить четыре filtered selections из README в последующую явно выбираемую manual qualification; успешные обычные
Unit/Gate/CLI/Lifecycle группы сами по себе не являются результатом P4. Actual packaged update проверен для активной
Node-задачи; остальные matrix-cases изолируют новые compatibility consumers. После merge дополнить их установленным
update/navigator replay, особенно для review-policy/rule-pack alignment и pre-sync handoff, не объявляя эти границы
пройденными по одному consumer smoke.

Не входит в P4: полный T-450 rebind/resume, authenticated verified-update receipt из feature/2.0, все V2/V3 adapters,
полная stack matrix, новые lifecycle действия и принятие релиза. Исходные коммиты 2.0 — источник решений, не cherry-pick.
Реальный model/provider review и native Linux/macOS здесь не заявляются. Облачный CI требует отдельного разрешения.
